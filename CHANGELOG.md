# Changelog

## 2026-07-06

### Monorepo scaffold

Initialized the repo as a pnpm workspace (`apps/*`, `packages/*`) — pnpm chosen over npm workspaces for stricter, symlinked `node_modules` that avoid phantom dependencies once `apps/web` starts importing from `packages/shared`.

- **`apps/web`** — Next.js 16.2.10 + TypeScript + Tailwind, scaffolded via `create-next-app` and stripped to a minimal starter: no landing page content, default assets removed, and the generator's nested `CLAUDE.md`/`AGENTS.md`/`pnpm-workspace.yaml` deleted so they don't shadow the repo root. Added `turbopack.root` in `next.config.ts` to fix workspace-root autodetection.
- **`apps/api`** — FastAPI + uvicorn, `pyproject.toml` using Poetry with PEP 621 `[project]` metadata (Poetry 2.x's preferred format). Single route: `GET /health` → `{"status": "ok"}`.
- **`packages/shared`** — holds only generated TypeScript, nothing hand-written. `src/generated.ts` is produced by `openapi-typescript` from the running FastAPI app's OpenAPI spec.
- **Codegen wiring** — root `pnpm run codegen` → `pnpm --filter shared run codegen` → `openapi-typescript http://localhost:8000/openapi.json -o src/generated.ts`. Verified end-to-end against a live `uvicorn` instance.
- **`docker-compose.yml`** — single `postgres` service on `pgvector/pgvector:pg17`, no app services yet. Verified the image boots and `CREATE EXTENSION vector` succeeds.
- **`.env.example`** for both apps — `apps/api` has `DATABASE_URL` + an `ANTHROPIC_API_KEY` placeholder (never a real key); `apps/web` only has `NEXT_PUBLIC_API_URL`, since the Anthropic key belongs server-side per the orchestration seam in `ARCHITECTURE.md`.
- Root `.gitignore` added; fixed a bug in `create-next-app`'s default `apps/web/.gitignore` where `.env*` would have silently excluded `.env.example` from version control (`!.env.example` negation added).
- Blank `CLAUDE.md` and `EVALS.md` stubs created at repo root, left empty for manual authoring.
- Root `README.md` documents pnpm/Poetry setup, `docker compose up`, running both apps, and the exact codegen command.

### Part 1 Postgres schema + seed data

Added the 6-table Part 1 schema as SQLAlchemy models + an Alembic migration (not raw SQL), plus a re-runnable seed script.

- **`apps/api/app/db/models.py`** — `Customer`, `Product`, `Order`, `OrderItem`, `Refund`, `SupportTicket`, matching the specified columns exactly: `refunds.order_item_id` attributes to a line item (not the order); all money fields are `_cents` integers; no stored `days_since_purchase` column; `support_tickets.order_id`/`.product_id` nullable for general inquiries.
- **`apps/api/alembic/versions/c432813f0cec_create_part_1_schema.py`** — autogenerated and verified against a running Postgres instance (`\dt`, `\d refunds`, `\di`). Includes the 4 required indexes: `refunds(order_item_id)`, `refunds(requested_at)`, `order_items(product_id)`, `support_tickets(product_id, created_at)`.
- **`apps/api/app/db/seed.py`** — truncates and reinserts deterministic fixture data on every run (`poetry run python -m app.db.seed`); verified idempotent by running it twice. Row counts: 20 customers, 20 products, 25 orders, 39 order_items, 20 refunds, 20 support_tickets.
- Baked-in edge cases, each verified with a direct SQL query post-seed:
  - One refund that's structurally valid (correct amount, `approved`) but is 60 days after purchase — violates the 45-day policy window only when `requested_at - order_date` is computed at query time.
  - A 3-item order (Bluetooth Headphones, Wireless Mouse, USB-C Charging Cable) where only the headphones line item is refunded — tests order_item-level attribution.
  - Two deliberately high-refund-rate products ("Bluetooth Headphones Pro", "Wireless Mouse - Refurbished"), each sold 5 times with 4 of 5 approved refunds (80% rate).
  - Near-duplicate/ambiguous product names across 5 families: Wireless Mouse (×3 variants), Water Bottle (×2), Headphones (×2), USB-C Cable (×2), Green Tea (×2).
  - Support tickets with both `order_id` and `product_id` null (general inquiries).
- Added `sqlalchemy`, `alembic`, `psycopg[binary]`, `python-dotenv` to `apps/api/pyproject.toml` / `poetry.lock`.
- Both READMEs updated with `alembic upgrade head` + `python -m app.db.seed` instructions.

Explicitly out of scope for both pieces of work (per instructions): `ARCHITECTURE.md` untouched, no query/retrieval logic, no RBAC/role fields, no auth, no CI, no deployment config.
